# Subscription browser handoff

This MVP uses the user's existing ChatGPT or Grok browser session. It does not automatically submit images, consume an API key, authenticate on the user's behalf, or claim that a subscription authorizes programmatic image editing. OpenAI's documented ChatGPT plan sign-in route currently excludes image-generation tools; xAI's API usage is separately billed. References: [OpenAI limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [xAI pricing](https://x.ai/pricing).

1. Load the backup save and facepack, then select a mapped newgen.
2. Choose hairstyle, beard and/or appearance age options. The age starts at the save's player age, with +5/+10/+15/+20 choices. The prompt editor stays collapsed initially and can be customized. Custom text is retained when presets change until explicitly reset; review it for consistency.
3. Click **Copy portrait + prompt** on the main screen. The clipboard contains PNG and bitmap image data, full prompt text, and an HTML fragment containing both. Open ChatGPT or Grok using the adjacent button, or switch to an existing browser chat. Sign in there and paste. Browser chat paste handlers may consume only the image despite all formats being present: use **More options → Copy prompt only** if that happens. The original portrait is also draggable directly into the browser.
4. Run the image edit in the browser. The stronger prompt requests PNG with real transparency and clean, naturally antialiased edges, with no black/colored halo, border, matte or bright edge specks.
5. Use the browser's **Copy image**, then **Paste edited image** or Ctrl+V in FFM. You can also drag/drop the finished image onto FFM. Native PNG clipboard data is preferred over converted bitmap data. Local image files, bitmap clipboard data, inline image data and public HTTPS image links are supported. Private/authenticated or blob-only browser links show guidance to use Copy image or the fallback file picker under **More options**. FFM does not read browser cookies. The optional browser handoff dialog remains under **More options**.
6. Import rejects a different aspect ratio, normalizes dimensions and preserves the original cutout alpha. Undefined colors in transparent generated pixels fall back to the original rather than becoming visible black pixels. **Reduce edge halos** restores RGB along the first two cutout pixels and blends the third pixel; it never globally removes red or dark colors. When available, the earliest readable sibling backup with identical dimensions and alpha is snapshotted as the edge-color reference, so already accepted fringes need not become the baseline. Toggle cleanup to compare the preview. The original silhouette is retained, so hairstyle changes extending beyond it can be clipped.
7. Review both panes. **Compare original** toggles the preview pane between the imported edit and the exported original. Identity preservation still requires visual review of the provider's result.
8. **Accept portrait** verifies source/config/preview hashes, writes and verifies the numbered sibling backup, then commits the edit. **Reject** discards the pending preview without modifying the facepack and permits another result to be pasted for the same prepared original. Changing player, presets or prompt invalidates the prepared original and any earlier preview. Version restoration stages with edge cleanup disabled to preserve the prior appearance.

Source exports and imported previews are held under `%LOCALAPPDATA%\FFM\edits`. Provider preference is stored locally without credentials. The browser upload is performed by the user; FFM opens only the provider homepage, with no image or prompt in the URL.

Before replacement FFM checks mappings under the enclosing graphics directory, including real players and icons. An exclusive PNG is atomically replaced after backup. A shared image, or a non-PNG original, becomes a new player-specific PNG; the original source remains untouched and all matching selected-player portrait mappings are updated. Conflicting selected-player mappings prevent acceptance. If matching selected-player configs fall outside the chosen root, select the broader graphics directory before editing.

Old portraits use sibling `<active-stem>_prev<number>.<original-extension>` files. Config preimages and transaction journals are stored under `%LOCALAPPDATA%\FFM\transactions`. Replacement stages live beside their destination to support atomic file replacement. Multi-file changes use a journal and rollback; they are not a single atomic filesystem operation. Startup recovery rolls back incomplete operations only when current hashes match the app's recorded changes, retaining externally changed files and backups for manual recovery.

Version history lists sibling backups and lets the user stage a restoration. Restoration follows the same preview and acceptance process and backs up the current portrait first. Refresh Football Manager's graphics cache after accepting a portrait.

`src/FFM.EditCheck` exercises the same native services using isolated synthetic images/configs. It covers preparation without source writes, dimensions/alpha, aspect-ratio rejection, exact backups and numbering, restoration, stale source/config/export rejection, real-player exclusion, shared-image isolation and scattered aliases, file-lock rollback, crash recovery and external-change protection. Clipboard checks cover combined formats, rich-content offsets, PNG preference, bitmap/file/inline/link input, size bounds and private-link failures with mocked HTTP. Pixel checks cover black/red boundary artifacts, preserved interior colors, exact alpha, missing color protection, cleanup opt-out and earlier-reference recovery. These checks never apply an edit to the user's real facepack or save, change the system clipboard or make live network requests.
